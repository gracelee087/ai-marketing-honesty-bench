# Which AI lies less in marketing copy?

A Kaggle Benchmarking Challenge project comparing 11 writers across 20 fictional early-stage companies, three formats and four factuality instructions. The primary score is the share of texts where a separate AI reader (`glm-5`) identifies zero unsupported claims. It is not human-verified factuality or a measure of marketing effectiveness.

The project tests how specific prompt instructions change AI marketing copy: banning invented numbers, restricting claims to supplied facts, and repeating the brief. Recurring language patterns are exploratory text measurements. The DEV draft explains the questions, controlled comparisons, actual outcomes and practical limits.

## Reproduce without model calls

Python 3.11.9 was used for the checked environment.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements-analysis.txt
python analysis/reproduce.py
python analysis/validate_submission.py
python -m unittest discover -s analysis -p "test_*.py"
```

No API keys, network access or Kaggle account are needed after dependency installation. The reproduction command verifies `results/manifest.json`, then writes tables and charts to `results/analysis`. To write elsewhere, add `--out path/to/output`.

The selected response bundle contains 2,898 generated texts and 2,665 reader-scored texts including repetitions. Main summaries use 2,208 scored first-repeat texts. `results/selected_runs` preserves generated copy, scorer results and numeric usage fields. Provider error text is omitted; unmeasured markers are normalized. The manifest records both original and exported file hashes.

## Interpret the results

The task crosses 20 companies × three formats × four instructions (240 items per writer). Pair 1 gets two additional repetitions, for 288 planned items. Main comparisons exclude those extra repetitions and exclude unscored texts. Cross-model tables use pairs 1–6; within-model and prompt summaries use all 20 companies. Missingness is not random: quotas disproportionately affected later companies.

Where multiple runs are available, select the one with the most reader-scored items, including repetitions; on a tie select the later run. Do not merge runs. See the dated addenda for the timing of these rules and the post hoc minimum of 30 scored core items.

The public Kaggle leaderboard uses all 20 companies. On October 6, its GPT-OSS 120B result was 18.18% from later run 4046443; this repository's selected run 3866186 has greater scoring coverage and scores 20.0% on the same all-company scope. The primary 12-company score for that selected run is 18.9%. The other ten live scores match the corresponding all-company saved-run scores. These scope and run-selection differences are retained explicitly.

Exploratory overlap, repetition, staffing and invitation-cue checks were chosen after seeing outputs. They do not measure sales quality. Invitation detection is a heuristic with regression tests, not human validation. `invitation_cues_audit.csv` includes every email, matched cue and sentence for inspection.

Machine-readable article counts are generated by `analysis/submission.py`. The three current English figures are generated by `analysis/design_submission_figures.py`, with PNG, SVG and provenance files under `results/analysis/hypothesis_views`. The three-check illustration intentionally excludes invitation cues. Its thresholds are disclosed and do not replace the original task score.

## New-company follow-up

The original exploratory findings motivated a separate follow-up with ten new company briefs. It compares the original request (A), the original facts-only instruction (C), and C plus one sentence allowing selective use of facts (E). The protocol, prompts, data, reader and analysis were locally frozen before the planned model runs. Every new brief contains a capability limitation, making this a targeted stress test. It includes no human ratings.

Reproduce the follow-up separately; it is not pooled with the original study:

```bash
python validation_2026-10-05/analyze.py
python validation_2026-10-05/inspect_results.py
python validation_2026-10-05/figures.py
```

The [protocol](validation_2026-10-05/PROTOCOL.md) includes the planned contrasts and missingness rules. [Operational repairs](validation_2026-10-05/README.md#registration-and-model-routing) document the zero-call registration and Sonnet model-routing attempts. Successful responses were not regenerated. Passing the thirty simple reader controls does not establish accuracy on natural marketing prose.

## Live task

`benchmark/marketing_honesty.py` is the version-4 task source used for these results. **Executing or importing it runs the benchmark** in the Kaggle environment; do not import it just to analyze saved responses. It is kept unchanged for provenance. `data/companies.json` holds the corresponding fictional briefs.

The live task depends on Kaggle's benchmark/model-proxy environment and may consume quota. The offline commands above do not use it. New outputs may differ from the saved run due to model/provider changes and nondeterminism.
